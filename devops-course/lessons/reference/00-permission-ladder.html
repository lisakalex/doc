The Permission Ladder

Every time a process opens a file, the kernel climbs four rungs and stops at the first one that matches. Only that rung's three bits count.

first match decides no fall-through updated 2026-11-20

The rungs

Who gets which row

RungThe kernel asksIf yesLibraryFrom your lab
1Is the process root (effective UID 0)? Read and write allowed, whatever the bits say. Execute still needs one x somewhere. The librarian, who can go anywhere passwd runs as root (setuid), so it can write /etc/shadow
2Is the process the file's owner? Use the owner bits, and stop The book's owner chmod 077 mine: owner row ---, so you can't read your own file
3Is the file's group one of the process's groups? Use the group bits, and stop A member of the book's club unix_chkpwd runs in group shadow, so it can read /etc/shadow (r--)
4Everyone else Use the other bits Everyone else You (al) on /etc/shadow: other ---, so "Permission denied"

Say it as a chain

Not root, so rung 1 is skipped. Not the owner, so rung 2 is skipped. Not in the file's group, so rung 3 is skipped. That leaves other, and its row says ---, so no read.

Reading a mode

One string, four fields

-type rw-owner r--group ---other

-rw-r----- 640 root:shadow /etc/shadow. Check who you are (id) against the owner and group (stat) first. The rwx letters only matter once you know which row is yours.

Deleting is a directory question

Removing a file changes the directory's list of names, so it needs w and x on the directory. The file's own bits don't matter. A sealed book can still be taken off an open shelf.

The fourth digit

Special bits

BitShows asDoesExample
setuid 4000s in the owner's x place The program runs as its file's owner, whoever starts it /usr/bin/passwd rwsr-xr-x 4755: RUSER al, EUSER root
setgid 2000s in the group's x place On a directory: new files inside take the directory's group /var/log/journal drwxr-sr-x 2755
sticky 1000t in other's x place On a directory: you can delete only your own files /tmp drwxrwxrwt 1777

A capital S or T means the special bit is set but the x under it isn't, which is usually a mistake (see Ansible mode: 644 unquoted).

The docker group is root

The Docker daemon runs as root, and a container's root is the host's root for any file you mount. docker run --rm -v /etc/shadow:/s:ro alpine wc -l /s read a root-only file with no sudo. Treat docker group membership like sudo access.
