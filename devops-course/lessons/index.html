Moving secrets into a better vault does not remove the key that opens it. The second run must end in changed=0. A shell task always reports changed, so it fires handlers on every run and hides real drift in the noise. devops/p0-4-ansible-idempotency-named.html 0.5 Python That Survives Leaving Your Laptop What import searches and why a script works on the laptop by accident; a venv as a directory; three failures reproduced on three Pythons; transitive drift replayed with --exclude-newer; pyproject against uv.lock; the wheel, and why it does not carry the lock. Ship the wheel and the hashed lock together, install with --require-hashes and --no-deps, and nothing is resolved on the server. devops/p0-5-python-that-survives.html 1.1 Where the Disk Space Went Why df and du disagree after rm; inodes, link counts and file descriptors; /proc/PID/fd and lsof +L1; four ways to rotate a log and what each does to the open file; descriptor inheritance and the Jenkins step that never ends; Too many open files. rm removes a name, not a file. The blocks are freed only when no name and no open descriptor is left, so a log rotation is only as good as the writer's reopen. devops/p1-1-where-the-disk-space-went.html 1.2 Where the Memory Went What free, buff/cache and available count; the page cache, measured; tmpfs as memory that can't be dropped; VSZ against RSS and overcommit; reclaim, swap and the OOM killer's choice; cgroup limits and exit code 137; how a JVM sizes its heap and the two ways it dies. Alert on available, not free. A process killed by its cgroup gets SIGKILL and leaves no stack trace, only exit 137 and a line in the kernel log. devops/p1-2-where-the-memory-went.html 1.3 The Job Nobody Saw Fail Why a cron job fails silently: its bare PATH and its output mailed to nowhere; systemd as every service's parent; a Java unit file line by line; Restart= and the start limit; systemd's own $ and % expansion; Environment=; journalctl; timers, Persistent=true and OnFailure=; drop-ins instead of editing a vendor's unit. A timer job is an ordinary service: its environment is written in the unit, its output is in the journal, a missed run is caught up, and a failure can start an alert. devops/p1-3-the-job-nobody-saw-fail.html 1.4 Running but Unreachable One request in five steps: DNS, the route, the TCP connection, TLS, HTTP. Interfaces and ip route; bind to 127.0.0.1 against 0.0.0.0 and ss -ltnp; the container localhost trap; refused against timed out; nsswitch, /etc/hosts and why dig disagrees; the five-second resolver timeout; curl's timing breakdown; certificate checks and Java's own cacerts. Find which step failed before fixing anything: refused means nobody is listening, timed out means something dropped it, and every call taking 5 seconds means DNS. devops/p1-4-running-but-unreachable.html 1.5 The File Root Left Behind How the kernel decides who may open a file: UIDs, groups and the owner, group, other check; directory bits and why deleting depends on the directory; namei; umask; groups read at login and the -a in usermod -aG; setuid, setgid and the sticky bit; root-owned files left by a manual run; Ansible's unquoted mode; User=, LogsDirectory= and UMask= in a system unit. The first matching row of the mode decides, owner before group before other. A file belongs to whoever created it, so one manual run as root can silence a service's log. devops/p1-5-the-file-root-left-behind.html 2.1 Ten Containers, One Image What a Docker image is on disk: read-only layers, one per RUN, COPY or ADD, named by their hash and shared between images; the container's writable layer; overlayfs, lowerdir and upperdir; copy-up of the whole file on the first write; whiteouts, why RUN rm doesn't shrink an image, and a deleted secret read back with docker save; docker ps -s, docker diff, docker history, docker system df -v; images run as root unless USER says otherwise. Ten containers from one image cost ten thin writable layers and one image. A layer never changes once built, so deleting a file later hides it and frees nothing. devops/p2-1-ten-containers-one-image.html

Module 02 · complete

IAM — identity and access

2.1 Identity Is Not Credential Users, roles, and the two policies that decide who may become what — read against a live audit of your own account. A role is an identity you become; a credential is a thing you hold. aws/21-identity-is-not-credential.html 2.2 How Role Assumption Works Two permission checks, at two different moments, against two different policies. Assuming a role replaces your permissions; it does not add to them. aws/22-how-role-assumption-works.html 2.3 Explicit Deny Wins How AWS decides yes or no — three rules in a fixed order, and the most common wasted afternoon in AWS. Explicit Deny beats Allow beats implicit deny. aws/23-explicit-deny-wins.html 2.4 The Missing Claim Two OIDC trust policies in your own terraform/. One is written the way AWS documents it; the other is missing a condition. A trust policy without a sub condition trusts the whole provider, not your repository. aws/24-the-missing-claim.html 2.5 The Key That Only Knocks The hands-on that reduced the readable key on your laptop to a single, MFA-gated capability. The static key can only knock on a door that does not open without MFA. aws/25-the-key-that-only-knocks.html 2.6 The Best Secret Is None Secrets Manager, Parameter Store, and the ranking that puts both below having no secret at all. Added after the module closed, from your own question. Where you run something determines which secret-management options exist at all. aws/26-the-best-secret-is-none.html

Module 03 · complete

S3 — object storage

3.1 Keys, Not Paths S3 looks like a filesystem in every screenshot and behaves like one in almost no way that matters. The key is one flat string; folders are grouping computed on read, and rename is copy then delete. aws/31-keys-not-paths.html 3.2 The Second Lock Why full S3 permission still fails the upload, and what envelope encryption actually does with your key. The key is a second, independent control surface: you can cut off access to data without touching bucket permissions. aws/32-the-second-lock.html 3.3 Cheaper Isn't Cheaper Every storage class below Standard advertises a lower price per gigabyte and attaches conditions that can raise your bill. The surprising money is in floors, minimum durations and requests — not in stored bytes. aws/33-cheaper-isnt-cheaper.html

Module 04 · complete

KMS — encryption

4.1 Rotation Rotates Nothing What enable_key_rotation = true does, what it deliberately does not do, and the four key states — one of which is final. Rotation adds key material; it never retires any, and it never touches your data. aws/41-rotation-rotates-nothing.html 4.2 The Key Says Who Key policies, the default policy your repo is using, the four conditions that tighten it, grants — and a runbook for “the key has been compromised”. IAM never grants access to a key on its own; the key policy must delegate first. aws/42-the-key-says-who.html 4.3 Nothing Breaks Until It Restarts The same key under EBS, RDS, DynamoDB and Secrets Manager: delayed failure, the seven-day clocks, grants that outlive people, request quotas and multi-Region keys. Outside S3 the key is on the lifecycle path, so the outage waits for the next restart. aws/43-nothing-breaks-until-it-restarts.html
